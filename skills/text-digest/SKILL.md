# Text Digest

把长文本压成可直接粘贴进聊天或邮件的结构化摘要。核心原则：**只保留原文有的信息，不补、不猜、不评价**。

## 触发条件

满足任一条即触发：

- 用户提供一段文本（粘贴、附件、文件路径），并要求总结 / 摘要 / 提炼 / 划重点 / 一句话说清
- 用户要求把会议记录、报告、访谈稿转成要点列表
- 用户要求"压缩到 N 字以内"或"给领导看的版本"

不触发：需要翻译、需要外部事实核查、需要改写为另一文体（如演讲稿）、代码或表格数据分析。

## 输入

| 字段 | 必填 | 说明 |
|---|---|---|
| `text` | 是 | 待压缩的原文。可以是聊天中粘贴的文本，也可以是一个本地文件路径 |
| `length` | 否 | 目标字数，默认 200–300 字；用户说"N 字以内"则以此为准 |
| `audience` | 否 | 读者身份，默认"通用"。影响措辞深浅，不影响信息取舍 |
| `focus` | 否 | 用户特别关心的主题，出现时优先保留相关段落 |

输入不足时：`text` 缺失才追问；`length` / `audience` / `focus` 缺失一律用默认值，不追问。

## 步骤

1. **读全文，不做部分采样。** 文本超过 1 万字时先分段标记（`[1]` `[2]` …），避免中段遗漏。
2. **抽事实。** 逐段提取：结论性陈述、数字与日期、决策、责任人、风险。丢弃修饰、举例、重复表述。
3. **定主线。** 用一句话回答"这段文字最想让读者知道什么"。写不出来说明原文结构松散，此时按段落主题归纳而非强行拔高。
4. **按下面的模板组织输出**，控制字数：
   - 一句话结论优先，不铺垫背景
   - 要点 3–6 条，每条一行，动词开头
   - 关键数字单列，保留原单位与口径
   - 待确认项只列原文明确悬置的问题，不自行提出疑问
5. **自检。** 逐条比对：摘要里的每个断言都能在原文找到出处吗？找不到就删。字数超了先砍例子，再砍次要要点，最后才压结论句。
6. **输出。** 直接在对话中给出，不写文件，除非用户明确要求保存。

## 输出

固定四段结构，无内容则整段省略（不写"无"）：

```
【结论】<一句话，≤40 字>

【要点】
- <动词开头的一条>
- …

【关键数字】<数字 + 口径 + 出处段落标记，可多行>

【待确认】<原文中明确未定的问题>
```

末尾附一行元信息：`原文约 N 字 → 摘要 M 字`。

## 调用示例

**用户输入**

> 帮我总结一下这段，200 字以内，给部门负责人看：
>
> 上周三的项目例会上，我们复盘了 Q3 交付情况。整体进度达成率 78%，低于年初设定的 90% 目标，主要缺口来自数据中台模块，该模块延后两周。客户侧反馈集中在报表导出速度，平均等待 8 秒，超出合同约定的 3 秒。会上确定由张伟牵头在 10 月底前完成导出服务的缓存改造，预计可将耗时压到 2 秒以内。预算方面，Q4 追加 15 万元用于购买缓存中间件，已报财务待批。另外，原定 11 月上线的移动端适配因人力不足暂缓，具体重启时间未定。

**期望输出**

```
【结论】Q3 交付达成率 78%，低于 90% 目标，缺口集中在数据中台；Q4 以缓存改造补性能短板。

【要点】
- 复盘 Q3：达成率 78%，数据中台模块延后两周是主要缺口
- 处理客户投诉：报表导出平均 8 秒，超合同 3 秒约定
- 定责改期：张伟牵头，10 月底前完成导出服务缓存改造，目标 2 秒内
- 追加预算：Q4 增加 15 万元采购缓存中间件，待财务审批
- 暂缓事项：移动端适配因人力不足推迟，重启时间未定

【关键数字】达成率 78%（目标 90%）｜导出耗时 8 秒（合同上限 3 秒，目标 ≤2 秒）｜追加预算 15 万元

【待确认】缓存中间件采购待财务审批；移动端适配重启时间未定

原文约 260 字 → 摘要 190 字
```

**检查点**：示例里的每个数字都能在原文找到；"补性能短板"是对后文改造成本的归纳，不是新增判断；没有评价团队"执行力不足"这类原文没有的话。
